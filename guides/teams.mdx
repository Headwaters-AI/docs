# Teams

A **team** is a named group of faces. Use teams to organize faces by project, client, department, or any other structure that fits your workflow.

The caller who creates a team automatically becomes its **manager** — the only account that can rename it, add or remove members, or delete it. Faces added to a team must be owned by the manager.

<Note>
All team endpoints require `Authorization: Bearer YOUR_API_KEY`.
</Note>

---

## Create a team

```bash
curl -X POST https://api.faces.sh/v1/teams \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "Platform Engineering"}'
```

```json
{
  "id": "940c0574-445e-44dd-a4f7-505d26882dc5",
  "name": "Platform Engineering",
  "kind": "team",
  "member_count": 0,
  "created_at": "2026-04-22T16:24:05.932712",
  "updated_at": "2026-04-22T16:24:05.932712"
}
```

Every team response includes:

- `kind` — `"team"` for explicit teams (the ones you create with `POST /v1/teams`); `"personal"` for the auto-created per-user team that always exists alongside every user account. See [Personal vs explicit teams](#personal-vs-explicit-teams) below.
- `member_count` — current number of faces in the team. `0` immediately after creation; updated on every read.

## List your teams

Returns every team you manage or belong to, including your personal team.

```bash
curl https://api.faces.sh/v1/me/teams \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json
{
  "object": "list",
  "data": [
    {
      "id": "62b6c0d5-...",
      "name": "alice",
      "kind": "personal",
      "member_count": 1,
      "created_at": "...",
      "updated_at": "..."
    },
    {
      "id": "940c0574-...",
      "name": "Platform Engineering",
      "kind": "team",
      "member_count": 4,
      "created_at": "...",
      "updated_at": "..."
    }
  ]
}
```

### Personal vs explicit teams

Every user account has exactly one **personal team** — created automatically at registration, named after the user's username, and managed by them. It's a convenient default container; it always shows up in `/v1/me/teams`. Filter or hide it client-side via the `kind` field.

Explicit teams — the ones you create with `POST /v1/teams` — return `kind: "team"`. The detection rule is mechanical: `kind` is `"personal"` when `team.name == manager.username`, otherwise `"team"`.

---

## Read a single team

```bash
curl https://api.faces.sh/v1/teams/TEAM_ID \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Callers who are neither a manager nor a member get **`404`** (not `403`) — the API deliberately hides the team's existence from outsiders.

---

## Rename a team

```bash
curl -X PATCH https://api.faces.sh/v1/teams/TEAM_ID \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "Platform Eng"}'
```

Manager only.

---

## Delete a team

```bash
curl -X DELETE https://api.faces.sh/v1/teams/TEAM_ID \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Manager only. Deleting a team detaches every member face before removing the team record itself. The faces themselves are not deleted.

## Members

A team's members are **faces the manager owns**. User accounts cannot be added. Each face can belong to any number of teams.

### List members

```bash
curl https://api.faces.sh/v1/teams/TEAM_ID/members \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json
{
  "object": "list",
  "data": [
    { "iam_id": "92937d6e-5b26-4bbf-8dcd-4945f07e0d2e" },
    { "iam_id": "6e41e9dc-8722-45b9-8eb3-caed208d4a37" }
  ]
}
```

### Add a face

Send either a single `iam_id` or a batch via `iam_ids`.

```bash
# Single
curl -X POST https://api.faces.sh/v1/teams/TEAM_ID/members \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"iam_id": "FACE_UID"}'

# Batch
curl -X POST https://api.faces.sh/v1/teams/TEAM_ID/members \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"iam_ids": ["FACE_UID_1", "FACE_UID_2"]}'
```

Re-adding an existing member is a no-op (idempotent).

#### Validation and errors

Every candidate is validated up front. If **any** one fails, the entire request is rejected and nothing is written.

| Case | Status |
| --- | --- |
| Valid face you own | `200` |
| Face is owned by someone else | `403` |
| Target is a user account, not a face | `400` |
| Target IAM does not exist | `404` |

### Remove a member

```bash
curl -X DELETE https://api.faces.sh/v1/teams/TEAM_ID/members/FACE_UID \
  -H "Authorization: Bearer YOUR_API_KEY"
```

The manager can remove any member. (A face's owner will also be able to remove their own face from shared teams once face publishing ships.)

## Quick reference

| Method | Path | Who can call |
| --- | --- | --- |
| `POST` | `/v1/teams` | any authenticated user |
| `GET` | `/v1/teams/{id}` | manager or member |
| `PATCH` | `/v1/teams/{id}` | manager |
| `DELETE` | `/v1/teams/{id}` | manager |
| `GET` | `/v1/teams/{id}/members` | manager or member |
| `POST` | `/v1/teams/{id}/members` | manager |
| `DELETE` | `/v1/teams/{id}/members/{iam_id}` | manager |
| `GET` | `/v1/me/teams` | any authenticated user |
