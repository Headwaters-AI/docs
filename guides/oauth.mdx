# OAuth Connections

Users on the **Connect plan** can link their OpenAI account to route all inference — both chat and compile interviews — through their ChatGPT subscription at no additional cost.

---

## List connected providers

```bash
curl https://api.faces.sh/v1/oauth \
  -H "Authorization: Bearer YOUR_KEY"
```

```json
[
  {
    "provider": "openai",
    "connected": true,
    "connected_at": "2026-03-15T10:30:00Z"
  }
]
```

---

## Connect OpenAI

The OAuth flow uses a browser redirect. First, get the authorization URL:

```bash
curl https://api.faces.sh/v1/oauth/openai/authorize \
  -H "Authorization: Bearer YOUR_KEY"
```

```json
{
  "authorize_url": "https://chatgpt.com/authorize?client_id=...&redirect_uri=..."
}
```

Open `authorize_url` in a browser. After approving, you'll be redirected back with an authorization code. The callback endpoint handles the token exchange automatically.

<Note>
  OAuth is only available on the Connect plan. Free and Standard plan users will receive `403 Forbidden`.
</Note>

---

## Disconnect a provider

```bash
curl -X DELETE https://api.faces.sh/v1/oauth/openai \
  -H "Authorization: Bearer YOUR_KEY"
```

```json
{
  "detail": "Disconnected openai"
}
```

---

## How OAuth affects billing

OAuth routing applies to **all inference** — both chat and compile interviews. When you send a request with an eligible model, the API automatically tries your OAuth connection first:

1. **OAuth** (Connect plan with active connection) — free, uses your ChatGPT subscription
2. **Credits fallback** — if OAuth fails or is unavailable, uses your credit balance at standard per-token rates

### Controlling fallback

By default, the `api_fallback` user preference is `false` — requests fail instead of falling back to paid system keys. You can change this via:

```bash
curl -X PATCH https://api.faces.sh/v1/user/preferences \
  -H "Authorization: Bearer YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"api_fallback": true}'
```

You can also override per-request with `"oauth_only": true` (chat) or `"interviewer_billing_source": "oauth"` (compile threads). Explicit request params always take precedence over stored preferences.

### OAuth failure responses

When OAuth fails and fallback is disabled, the API returns:

```json
HTTP 422
{
  "error": "oauth_rejected",
  "detail": "Your OpenAI account rejected the request: ...",
  "upstream_status": 400,
  "fallback_available": true
}
```

| Field | Description |
|-------|-------------|
| `error` | Always `"oauth_rejected"` — stable code for client switching |
| `detail` | Raw error message from upstream |
| `upstream_status` | HTTP status from OpenAI (400 = model issue, 401 = token revoked, 429 = rate limit) |
| `fallback_available` | `true` if the user has credit balance for retry |

### Response headers

All chat proxy responses include:

| Header | Description |
|--------|-------------|
| `X-Faces-Provider` | `"openai-codex"` (OAuth, free) or `"openai"` (system key, charged) |
| `X-Faces-Cost-USD` | Cost charged for this request |
| `X-Faces-Routed-Endpoint` | Present when `/chat/completions` auto-routes: `"/v1/responses"` or `"/v1/messages"` |

### Compile threads

Compile interviews use OAuth automatically for Connect plan users. The `interviewer_billing_source` field in the response shows which path was used (`"oauth"` or `"credits"`).
